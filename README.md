1. How did you handle the concurrency race condition?
   
At first I tried to put synchronized on the processTransaction method in the service layer, but then realized if we ever scale the service or run multiple instances, an in-memory lock won't help at all.So I moved the locking directly to the database level using Spring Data JPA:  Pessimistic Locking for Wallet balance: In the repository, I used @Lock(LockModeType.PESSIMISTIC_WRITE) with a custom query SELECT w FROM Wallet w WHERE w.userId = :userId. This basically does SELECT ... FOR UPDATE in SQL. When 10 requests hit the server at the exact same millisecond, the database puts an exclusive lock on that specific wallet row. The requests have to wait their turn. Once the balance hits 0 after 5 transactions, the rest fail with InsufficientFundsException (mapped to HTTP 400).  Database Unique Constraint for Idempotency: For the duplicate webhooks, I put @Column(unique = true) on the transactionId in the entity. If 3 identical requests come in at the same time, the first one saves fine, and the other two trigger a DataIntegrityViolationException from H2, which I catch and return a 409 Conflict status code.


2. Where did your AI assistant give you an incorrect or sub-optimal suggestion?

Suggested in-memory tracking: The AI first suggested using a ConcurrentHashMap or a HashSet to store transaction IDs in memory before hitting the database. I noticed this has two flaws: first, it creates a check-then-act race condition where two threads can check .containsKey() at the exact same moment before either puts the key in. Second, keeping IDs in memory will eventually eat up all the heap memory if millions of transactions come in.Crashed my test suite with TestRestTemplate: When writing the tests, the AI told me to use @Autowired private TestRestTemplate restTemplate. When I ran the test in IntelliJ, it failed to even start and threw NoClassDefFoundError: org/springframework/boot/http/client/HttpComponentsHttpClientBuilder$TlsSocketStrategyFactory. The AI didn't realize my Spring Boot version was missing the Apache HTTP client dependency. I fixed it by throwing out TestRestTemplate and just using standard Java HttpClient (java.net.http.HttpClient) which is built right into the JDK and doesn't need extra pom dependencies.
